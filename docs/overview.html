What it is

A limit order book is the data structure at the heart of every exchange. It holds all open buy orders (bids) and sell orders (asks), sorted by price. When a new order arrives that is willing to pay at least what a seller asks (or sell for at most what a buyer bids), the book matches them and produces trades.

Orderly Chaos is a fast, embeddable implementation of that data structure with price-time priority matching: the best price trades first, and among orders at the same price, the oldest trades first. It is a library, not a server: you call it from C++, C, or Python and decide yourself where orders come from and what to do with the trades.

Use cases

Use caseHow Orderly Chaos is used
Market data replayRebuild the book of an instrument from an exchange's order-by-order feed (add, cancel, execute messages) and read best bid/ask, depth, and volumes at any point in time.
BacktestingSimulate where a strategy's orders would rest in the queue and when they would fill, instead of assuming fills at the last price.
Exchange and venue simulatorsUse the book as the matching core of a paper-trading venue, a game, a classroom exchange, or an internal crossing engine.

TeachingShow exactly how price-time priority, partial fills, and immediate-or-cancel orders behave, with runnable examples in three languages.

When to use it

A good fit when you need

  • One continuous, price-time priority book per instrument
  • Limit, market (immediate-or-cancel), cancel, and reduce operations
  • Integer prices in ticks, with no floating-point drift
  • Millions of operations per second in a single thread
  • The same engine from C++, C, Python, or any C FFI
  • Exact, tested semantics you can reason about

Look elsewhere if you need

  • A complete exchange (networking, risk checks, persistence, accounts)
  • Pro-rata, auction, or other non price-time allocation
  • Order types such as stop, iceberg, fill-or-kill, or post-only (build them on top)
  • Many threads writing to the same book without your own synchronisation
  • Fractional prices that cannot be expressed as integer ticks

Core concepts

Side
BUY orders form the bids; SELL orders form the asks.
Price
An unsigned 64-bit integer number of ticks. Choose the tick to suit the instrument, for example cents (10050 means 100.50). Zero is reserved and is never a valid limit price.
Quantity
An unsigned 32-bit integer number of units (shares, contracts, lots). Must be at least 1.
Order ID
An unsigned 64-bit integer chosen by you. It must be unique among resting orders; once an order is filled or cancelled its ID may be reused.
Price level
All resting orders at one price on one side, kept in arrival order (a FIFO queue).
Taker and maker
The incoming order that trades immediately is the taker; the resting order it trades against is the maker.

Matching rules

  1. Price priority. An incoming buy trades with the lowest ask first; an incoming sell trades with the highest bid first.
  2. Time priority. Among resting orders at the same price, the oldest trades first.
  3. Maker price. Every trade executes at the resting (maker) order's price. An aggressive buy at 105 against an ask at 100 trades at 100.
  4. No trade-through. A limit order never trades at a price worse than its limit.
  5. Atomic validation. A rejected request leaves the book exactly as it was.

Limit orders

The call returns the quantity filled immediately. Whatever is left rests in the book until it is filled by later orders, reduced, or cancelled.

Market orders

A market order trades against the opposite side, best price first, until it is filled or that side is empty. It never rests: any unfilled remainder is discarded (immediate-or-cancel). Its ID only labels the trades it produces, so it does not need to be unique. The call returns the quantity filled.

Cancel and reduce

  • Cancel removes a resting order completely.
  • Reduce lowers a resting order's quantity without losing its place in the queue. Reducing by the full open quantity cancels the order.

Order lifecycle

Trade events

Register a handler to receive one Trade per execution:

FieldMeaning
taker_idID of the incoming order
maker_idID of the resting order it traded with
taker_sideSide of the incoming order
priceExecution price (the maker's price)
quantityExecuted quantity
maker_remainingMaker's open quantity after the trade; 0 means it was fully filled and left the book

Handlers run after the operation has fully updated the book, in execution order. They may query the book but must not modify it. If a handler raises, the remaining trades of that operation are still delivered and the first error is raised from the call that caused them.

Errors

Every rejection names the failed operation, states the reason, and carries the symbolic status code in brackets, so the same failure reads the same way in every language. For example, cancelling order 99 when it is not resting reports cancel order 99: unknown order id [OC_ERR_UNKNOWN_ORDER_ID] in Python and unknown order id [OC_ERR_UNKNOWN_ORDER_ID]: no resting order with id 99 in C++. Query the book first (has() / oc_book_has) when an ID may already be gone.

In C++ every rejection throws orderly_chaos::OrderBookError: code() returns the ErrorCode, code_name() returns the matching OC_ERR_* name, and what() combines the reason with the order details. A rejected call never modifies the book.

Threads

A book is a single-threaded data structure, which is what makes it fast. Use one book per instrument and drive each book from one thread, or protect it with your own lock. The Python binding calls the library while holding the GIL, so sharing a Python book between threads is memory-safe; each individual call is atomic, but sequences of calls (such as has() followed by cancel()) are not.

Glossary

Best bid / best ask
The highest buy price and the lowest sell price in the book (the top of book).
Spread
Best ask minus best bid.
Mid price
The midpoint of the best bid and ask, rounded down to a whole tick.
Depth
The aggregated volume and order count at each price level, best first ("level 2" data).
Crossing
An order whose price reaches the best opposite price, and therefore trades immediately.
