The engine is a header-only C++17 core. Two thin layers expose it to other languages without duplicating any logic.

Object model

Data structures

Each operation touches only the structure that makes it cheap:

Ordered price levels: std::map

Each side keeps its price levels in a red-black tree (std::map<Price, Limit*>), so adding or removing a level is O(log L) in the number of levels L, guaranteed, whatever order prices arrive in. Before v0.2.0 an unbalanced binary tree was used; steadily rising or falling prices turned it into a linked list and made each new level O(L). The benchmarks show the difference.

Level index: tsl::robin_map

A hash map from price to level gives O(1) access to an existing level, so an order joining a price that is already in the book never touches the tree.

FIFO queues: intrusive doubly linked lists

Orders are themselves the nodes of their level's queue (prev/next pointers). Appending, and unlinking any order, are O(1) with no extra allocation. The head of the best level is always the next order to trade.

Cached aggregates

Each side caches its best level, total volume, and order count; each level caches its volume and count. They are updated incrementally, so top-of-book and volume queries are O(1).

Order index: std::unordered_map

Maps every resting order ID to its Order. Cancel, reduce, and lookup hash straight to the order, then follow its limit pointer to its level. The map's node-based storage keeps order addresses stable, which the intrusive queues rely on.

Memory and ownership

  • The book owns every Order (in the order index) and each side owns its Limit objects; all are released by RAII when the book is cleared or destroyed.
  • Books are movable but not copyable: copying would duplicate raw queue pointers.
  • Memory grows with resting orders and levels, not with the number of operations. Trade events reuse one buffer.
  • References returned by get() are invalidated by the next modifying call. The C and Python APIs return copies.

Error boundaries

Validation always happens before any state changes, so every rejected request leaves the book untouched. If memory allocation fails part way through matching, the book is still left consistent: the incoming order is dropped and the trades that already happened are kept.

Design decisions

Integer prices
Prices are integer ticks. Floating-point prices cannot be compared or hashed reliably, which would break price levels.
Balanced tree plus hash index
The tree guarantees O(log L) worst-case level changes and ordered depth walks; the hash index keeps the common case (joining an existing level) O(1).
Deferred trade delivery
Delivering trades after the book is consistent lets handlers query the book safely and keeps the book valid even if a handler throws.
Exceptions in C++, status codes in C
Idiomatic in each language; the C layer guarantees no exception crosses an FFI boundary.
ctypes.PyDLL
Plain ctypes.CDLL releases the GIL during calls, which would let two Python threads enter the non-thread-safe book at once. PyDLL keeps the GIL held, making shared use memory-safe at no cost.
