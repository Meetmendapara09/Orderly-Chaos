Architecture & Design

Orderly Chaos is built on a foundation of efficient data structures and a modular design that enables high-performance order matching at microsecond latencies.

Core Components

1. LimitOrderBook Class

The LimitOrderBook class is the central component, managing:

  • Sell Side (Asks): LimitTree<Side::Sell>
  • Buy Side (Bids): LimitTree<Side::Buy>
  • Order Store: std::unordered_map<UID, Order>

2. LimitTree

A custom red-black tree implementation (from vendor/binary-search-tree) that stores price levels (Limit nodes) in sorted order for O(log n) lookups. The tree is augmented with:

  • Best pointer: Points to the best price level for quick access
  • Volume accumulator: Aggregates total volume across all levels
  • Count accumulator: Tracks order count across all levels
  • Last best price: Tracks the previous best price for price movement detection

3. Order Structure

struct Order {
    UID uid;           // unique order ID
    Side side;         // buy or sell
    Quantity quantity; // shares in this order
    Price price;       // price of the order
    Limit* limit;      // pointer to containing price level
    Order* prev;       // previous order at this price level
    Order* next;       // next order at this price level
};

4. Limit Structure

struct Limit {
    Price key;             // price level
    Volume volume;         // total volume at this price
    Count count;           // orders at this price
    Order* head;           // first order (time-priority queue)
    Order* tail;           // last order
    Limit* next;           // next price level
    Limit* prev;           // previous price level
};

Matching Algorithm

Price-Time Priority

Orders are matched using the price-time priority rule:

  1. Orders at the best price are matched first (price priority)
  2. Among orders at the same price, earlier orders are matched first (time priority)

Limit Order Flow

1. New limit order arrives
2. Order is stored in the UID → Order map
3. If price crosses the spread:
   a. Execute market order against opposing side
   b. Match orders at each price level (best first)
   c. Remove filled orders
4. If order not fully filled:
   a. Insert remaining quantity into the LimitTree
5. Update tree aggregates (volume, count, best pointer)

Market Order Flow

1. New market order arrives (no price limit)
2. Match against best orders on opposing side
3. Consume liquidity level by level
4. Remove exhausted price levels
5. Update all affected aggregates

Build System

Orderly Chaos uses SCons as its build system, configured via SConstruct:

# Build the shared library
scons

# Run C++ tests
scons test

# Run benchmarks
scons benchmark

Layered Architecture

Layer 1: C++ Core
The LOB::LimitOrderBook class with all matching logic. Headers in include/, sources in src/.
Layer 2: C API
extern "C" functions in lib_lob.hpp that wrap the C++ class for FFI compatibility.
Layer 3: Python ctypes
library.py loads the shared library via ctypes, and orderly_chaos.py provides the high-level Python interface.
