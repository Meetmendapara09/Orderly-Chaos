System Architecture

Orderly Chaos is built on efficient data structures with a layered architecture for maximum performance and maintainability.

Layer 1: C++ Core

The core engine in include/limit_order_book.hpp implements the full order book logic with price-time priority matching. This is where all the performance-critical code lives.

Layer 2: C API

The include/lib_lob.hpp file provides an extern "C" interface that wraps the C++ class, enabling FFI from Python and other languages.

Layer 3: Python ctypes

orderly_chaos/library.py loads the shared library and configures ctypes function signatures. orderly_chaos/orderly_chaos.py provides the high-level Python interface.

Data Structures

LimitTree (Red-Black Tree)

Each side of the book (buy/sell) is stored in a red-black tree from the vendor/binary-search-tree library. The tree is augmented with:

  • Best pointer: O(1) access to the best price level
  • Volume accumulator: O(1) total volume query
  • Count accumulator: O(1) order count
  • Last best price: Tracks previous best for price movement detection

Order Store (Hash Map)

An std::unordered_map<UID, Order> provides O(1) lookup by order ID for cancellation and reduction operations.

Doubly-Linked Lists

At each price level, orders are stored in a doubly-linked list (from vendor/doubly-linked-list), maintaining time-priority order with O(1) insertion and removal.

Matching Algorithm

Price-Time Priority

Orders are matched following strict price-time priority:

  1. Price Priority: Best prices are matched first (highest bid / lowest ask)
  2. Time Priority: Among orders at the same price, earliest orders are matched first

Limit Order Flow

1. New limit order arrives
2. Order stored in UID → Order hash map
3. Check if price crosses the spread
   → Yes: Execute market-like matching at limit price
   → Remaining: Insert into LimitTree
4. Update tree aggregates (volume, count, best)

Market Order Flow

1. Market order arrives (no price limit)
2. Match against best orders on opposing side
3. Consume liquidity level by level
4. Remove exhausted price levels
5. Update all aggregates

Build System

The project uses Bazel (with Bzlmod) as its build system, configured via MODULE.bazel and per-package BUILD.bazel files. Tests use Google Test (gtest), vendored under vendor/googletest. Build targets:

bazel test //test:all                          # Run C++ unit tests
bazel test //benchmark:benchmark_lob_test      # Run performance benchmarks
bazel build //src:lib_orderly_chaos.dll        # Build shared library
bazel build //main:dummy_matching              # Build example binary
