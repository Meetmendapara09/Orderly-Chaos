Prerequisites

Orderly Chaos is a C++17 engine with Python bindings built by Bazel. You need a compiler, Python, and Bazel — everything else is fetched automatically. Check each requirement before you start:

ToolRequired VersionNotes
C++ compilerGCC 7+ or Clang 6+ with -std=c++17Any recent GCC/Clang works (gcc.gnu.org). MSVC is not tested — use MinGW-w64 on Windows.
Python3.8+Needed only for the Python bindings (docs.python.org). The C++ core builds without Python.
Bazel7+ with Bzlmod enabledInstall via bazel.build/install (Windows guide: bazel.build/install/windows). Bzlmod is on by default in Bazel 7+.
Windows onlyMinGW-w64 via Strawberry Perl, plus Git for Windows (or MSYS2) for bash.exeBazel requires a POSIX shell on Windows — see Troubleshooting. The custom toolchain lives in toolchain/BUILD.bazel.

Verify your setup in one shot:

g++ --version        # should show GCC 7+ or Clang 6+
python --version     # should show 3.8+
bazel --version      # should show 7.x or 8.x
# Windows: confirm MinGW is where the toolchain expects it
ls "D:/Strawberry/c/bin/g++.exe"  # or wherever your g++ lives

Installation

Choose the path that fits you. Most users want Option A.

Option A — Python from PyPI (fastest)

If you just want to use the engine from Python, no build needed:

pip install orderly-chaos

Then jump to Quick Start.

Option B — Build from source (all platforms)

Clone, build the shared library, and install the Python package in editable mode. Every command below is copy-paste ready.

# 1. Clone
git clone https://github.com/Meetmendapara09/Orderly-Chaos.git
cd Orderly-Chaos

# 2. Tell Bazel where bash lives (Windows + Git Bash users — required once per shell)
#    If you use Command Prompt:  set BAZEL_SH=C:\Program Files\Git\bin\bash.exe
export BAZEL_SH="C:/Program Files/Git/bin/bash.exe"   # Git Bash / MSYS2

# 3. Build the shared library
bazel build //orderly_chaos:copy_dll

# 4. Copy the DLL next to the Python package (so ctypes can find it)
cp bazel-bin/orderly_chaos/lib_orderly_chaos.dll orderly_chaos/

# 5. Install the Python package
pip install -e .

What just happened? //orderly_chaos:copy_dll compiles the C++ core and C API into lib_orderly_chaos.dll (or .so on Linux/macOS) and copies it into the build output. The cp step places it where orderly_chaos/library.py expects it at runtime.

First build? The very first command downloads all external dependencies declared in MODULE.bazel (Bzlmod resolves them automatically; you can pre-fetch with bazel fetch //...). Google Test is pinned by SHA-256 via http_archive, so builds are hermetic — everyone gets the exact same sources. Subsequent builds are incremental and cached.

Option C — C++ only (no Python)

Just copy the headers — the engine is header-only for C++ consumers:

cp -r include/ your_project/include/

Then #include "limit_order_book.hpp" and compile with -std=c++17 -O2. No Bazel required for this path.

Quick Start

Prices are integers (e.g., cents). Pass 10250 for $102.50 — this avoids floating-point rounding in matching.

Python — your first book in 6 lines

from orderly_chaos import LimitOrderBook

book = LimitOrderBook()

# Place two limit orders that do not cross
book.limit_sell(order_id=1, quantity=100, price=10250)  # ask $102.50
book.limit_buy(order_id=2, quantity=50, price=10240)   # bid $102.40

# A market buy that lifts 75 shares from the ask
book.market_buy(order_id=3, quantity=75)

# Inspect the book
print(f"Best Ask: ${book.best_sell() / 100:.2f}")   # 102.50 (25 shares remain)
print(f"Best Bid: ${book.best_buy() / 100:.2f}")    # 102.40
print(f"Total Volume: {book.volume()}")             # 75

C++ — same flow, zero overhead

#include "limit_order_book.hpp"
#include <iostream>

int main() {
    LOB::LimitOrderBook book;

    book.limit_sell(1, 100, 10250);
    book.limit_buy(2, 50, 10240);
    book.market_buy(3, 75);

    std::cout << "Best ask: " << book.best_sell() << std::endl; // 10250
    std::cout << "Volume: " << book.volume() << std::endl;     // 75
    return 0;
}

Compile with: g++ -std=c++17 -O2 -Iinclude main.cpp -o book

# Performance benchmark

# Python tests (after pip install -e .)
python -m unittest discover -v
# expect: 15 tests OK

Python Guide

All operations go through LimitOrderBook. Order IDs must be unique — reusing an ID without cancelling first will throw.

Creating a book

from orderly_chaos import LimitOrderBook
book = LimitOrderBook()  # empty book, zero volume

Placing limit orders

# Explicit side methods (recommended for readability)
book.limit_sell(order_id=1, quantity=100, price=10250)
book.limit_buy(order_id=2, quantity=50, price=10240)

# Generic method — side=True means buy, False means sell
book.limit(side=True, order_id=3, quantity=75, price=10230)

If a new limit order crosses the spread (e.g., you buy at or above the best ask), it matches immediately like a market order for the crossing portion. Any leftover quantity rests in the book.

Market orders

book.market_buy(order_id=4, quantity=25)   # lifts from the ask side
book.market_sell(order_id=5, quantity=25)  # hits the bid side

Querying the book

book.best_sell()        # lowest ask, 0 if no asks
book.best_buy()         # highest bid, 0 if no bids
book.best(True)              # generic: True=bid, False=ask
book.volume()           # total shares in book
book.volume(10250)           # shares resting at price 10250
book.count()            # total number of orders
book.has(1)             # True if order 1 still rests
book.cancel(1)          # remove order 1
book.clear()            # remove everything

C++ Guide

Include one header. All types live in namespace LOB.

#include "limit_order_book.hpp"
#include <iostream>

using namespace LOB;

int main() {
    LimitOrderBook book;

    // Place limit orders
    book.limit_sell(1, 100, 10250);
    book.limit_buy(2, 50, 10240);

    // Market order — consumes from opposite side
    book.market_buy(3, 25);

    // Query — all O(1) except count_at (O(log n))
    std::cout << book.best_sell() << std::endl;
    std::cout << book.volume() << std::endl;
    std::cout << book.count() << std::endl;

    // Manage orders
    book.cancel(1);
    book.clear();

    return 0;
}

Key C++ notes: price and quantity are integer types (Price = uint64_t, Quantity = uint32_t). The book owns its orders — use has()/get() to inspect before cancelling.

C API Guide

The C API (include/lib_lob.hpp) wraps the same engine with extern "C" so any language with a C FFI can call it. Python's ctypes layer is built on top of it.

#include "lib_lob.hpp"

int main() {
    // Create — returns an opaque pointer
    LOB::LimitOrderBook* book = new_();

    // Place orders (same semantics as C++)
    limit_sell(book, 1, 100, 10250);
    limit_buy(book, 2, 50, 10240);
    market_buy(book, 3, 25);

    // Query
    LOB::Price best_ask = best_sell(book);
    LOB::Volume vol = volume(book);

    // Cancel and free — you own the book pointer
    cancel(book, 1);
    delete_(book);

    return 0;
}

Every new_() must be paired with delete_(). See C API reference for the full function list.

Troubleshooting

Error: BAZEL_SH not set / sh_toolchain failed

ERROR: Cannot determine sh_toolchain ... BAZEL_SH not set

Bazel on Windows requires a POSIX-compatible shell and needs to be told where bash.exe lives — from Git for Windows or MSYS2 (x86_64 build, not i686/MSYS — per the official Bazel-on-Windows guide). Fix: 

# Git Bash / MSYS2 — run before every bazel command, or add to ~/.bashrc
export BAZEL_SH="C:/Program Files/Git/bin/bash.exe"

# Command Prompt
set BAZEL_SH=C:\Program Files\Git\bin\bash.exe

# PowerShell
$env:BAZEL_SH="C:/Program Files/Git/bin/bash.exe"

Verify: echo $BAZEL_SH should print the path, and ls "$BAZEL_SH" should exist.

Error: g++.exe not found / toolchain misconfigured

error: could not find g++.exe in STRAWBERRY_BIN

The Bazel toolchain hard-codes the MinGW path in toolchain/BUILD.bazel:14:

STRAWBERRY_BIN = "D:/Strawberry/c/bin"  # default

If your Strawberry (or standalone MinGW) is elsewhere, edit that line to your g++.exe directory, e.g. "C:/msys64/mingw64/bin". Then bazel clean and rebuild.

Python: DLL load failed or FileNotFoundError

orderly_chaos/library.py loads lib_orderly_chaos.dll from the package directory via ctypes.CDLL. Windows raises OSError: [WinError 126] when the DLL (or a runtime it depends on) is missing. If you built from source but skipped the copy step: 

cp bazel-bin/orderly_chaos/lib_orderly_chaos.dll orderly_chaos/
pip install -e .  # reinstall so Python sees it

Python version too old

The bindings require Python 3.8+. If python --version shows 3.7 or older, upgrade Python or use a virtual environment with a newer interpreter. The C++ core still builds fine without Python.

Still stuck?

Run with verbose output and open an issue with the log:

bazel test //test:all --test_output=streamed --verbose_failures
