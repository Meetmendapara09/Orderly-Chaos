Requirements

To useYou need
Python packagePython 3.9 or newer, pip, and a C++17 compiler (GCC 7+, Clang 5+, Xcode command line tools, or MSVC 2019+)
C++ libraryA C++17 compiler. The core is header-only; no build step is required.
C API / shared libraryA C++17 compiler, plus Bazel 7+ (or Bazelisk) if you build with Bazel
Running the test suitesBazel 7+ for C++ tests; Python 3.9+ for Python tests

Python

Install the latest release from PyPI (no compiler needed):

python -m pip install orderly-chaos

Or install from a clone of the repository, in which case pip compiles the native library for your platform automatically:

git clone https://github.com/Meetmendapara09/Orderly-Chaos.git
cd Orderly-Chaos
python -m pip install .

For development, install in editable mode with the test dependencies:

python -m pip install -e ".[test]"
python -m pytest
Using a library built elsewhere

Set ORDERLY_CHAOS_LIBRARY to the path of a shared library built with Bazel (or copied from another machine with the same platform) to make the Python package load it instead of searching its own directory.

C++

The C++ API is header-only. Add two include directories to your build and include one header:

g++ -std=c++17 -O2 -I include -I third_party/robin_map/include app.cpp -o app
#include <orderly_chaos/orderly_chaos.hpp>

With Bazel, depend on the library target from your own module:

cc_binary(
    name = "app",
    srcs = ["app.cpp"],
    deps = ["@orderly_chaos//:orderly_chaos"],
)

C and other languages

Build the shared library, which exports the C API declared in include/orderly_chaos/orderly_chaos.h:

bazel build //:shared_lib
# bazel-bin/lib_orderly_chaos.so     (Linux)
# bazel-bin/lib_orderly_chaos.dylib  (macOS)
# bazel-bin/lib_orderly_chaos.dll    (Windows)

Link it from C, or load it from any language with a C foreign-function interface (Rust, Go, C#, Java, Julia, and others). Bazel users can link the static //:orderly_chaos_c target instead.

Windows notes

The Bazel build uses the MinGW-w64 toolchain bundled with Strawberry Perl, registered in toolchain/BUILD.bazel. Edit STRAWBERRY_BIN there if your g++.exe lives elsewhere. Bazel also needs a bash; put machine-specific settings like this in a git-ignored user.bazelrc at the repository root: 

build --shell_executable="C:/Program Files/Git/bin/bash.exe"

The pip installation uses your regular MSVC compiler and does not need Bazel.

Docker

A ready-made image runs the quickstart demo with no local toolchain:

docker run --rm ghcr.io/meetmendapara09/orderly-chaos:latest
docker run --rm ghcr.io/meetmendapara09/orderly-chaos:latest python examples/python/replay_events.py

Build it yourself, or run the test suite inside the image:

make docker-build   # runtime image
make docker-test    # full Python suite in the image

Verify the build

make test             # C++ tests, examples, and the Python suite
bazel test //...      # everything Bazel knows about
python -m pytest      # Python tests only (after pip install -e .)

All suites should pass. The C++ suite includes a randomized test that compares the engine with an independent reference model over more than 80,000 operations.

Your first order book

  1. Create a book and listen for trades.

    from orderly_chaos import LimitOrderBook, Side

trades = []
book = LimitOrderBook(on_trade=trades.append)

  2. Add resting orders. Prices are integer ticks; here one tick is one cent.

    book.limit(Side.SELL, order_id=1, quantity=100, price=10_050)  # ask 100 @ 100.50
book.limit(Side.SELL, order_id=2, quantity=200, price=10_075)  # ask 200 @ 100.75
book.limit(Side.BUY,  order_id=3, quantity=150, price=10_000)  # bid 150 @ 100.00
print(book.best_buy(), book.best_sell(), book.spread())        # 10000 10050 50

  3. Send an order that crosses the spread. It trades what it can and rests the rest.

    filled = book.limit(Side.BUY, order_id=4, quantity=250, price=10_050)
print(filled)                  # 100 (all of order 1)
print(book.get(4).quantity)    # 150 still resting at 10050
print(trades[0])               # Trade(taker_id=4, maker_id=1, taker_side=<Side.BUY: 1>, price=10050, quantity=100, maker_remaining=0)

  4. Inspect the book.

    for level in book.depth(Side.BUY, levels=5):
    print(level.price, level.volume, level.count)
# 10050 150 1
# 10000 150 1

Continue with the examples or the API reference for Python, C++, or C.

Project layout

include/orderly_chaos/   Public headers: C++ API (*.hpp) and C API (orderly_chaos.h)
src/                     C API implementation (the shared library)
python/orderly_chaos/    Python package (ctypes bindings)
tests/cpp/               C++ tests (GoogleTest)
tests/python/            Python tests (unittest / pytest)
examples/                Runnable C++, C, and Python examples
benchmarks/              Micro-benchmarks
docs/                    This documentation site and design notes
third_party/             Vendored dependencies (tsl::robin_map, GoogleTest build file)
toolchain/               Optional MinGW-w64 toolchain for Windows

Troubleshooting

LibraryError: the Orderly Chaos native library was not found

The Python package could not find its compiled library. Reinstall with pip install ., run make python-lib in a source checkout, or point ORDERLY_CHAOS_LIBRARY at a built library.

"built from an incompatible version" or a version mismatch

A library from a different release is being loaded (for example, a stale file left in python/orderly_chaos/). Delete it and rebuild with make python-lib or pip install -e ..

pip fails with "command 'g++' failed" or "Microsoft Visual C++ is required"

Install a C++17 compiler: build-essential on Debian/Ubuntu, xcode-select --install on macOS, or the "Desktop development with C++" workload of Visual Studio Build Tools on Windows.

could not find g++.exe (Windows, Bazel)

Update STRAWBERRY_BIN in toolchain/BUILD.bazel to the directory containing your MinGW g++.exe, then run bazel clean.

Still stuck?

Run the failing command with --verbose_failures (Bazel) or -v (pip) and open an issue with the output, your operating system, and compiler version.
